Co robi się TUTAJ, w pętli
Wszystko, co agent może zrobić i powtórzyć: czytanie i edycja plików, uruchamianie testów i buildów (core.exec), wyszukiwanie, delegacja do subagenta (core.agent_spawn) i pytania do Ciebie (core.ask_user oraz prośby o zgodę).
Czerwone testy nie są rozgałęzieniem grafu. Agent widzi wynik jako rezultat narzędzia, poprawia kod i odpala je znowu — kolejna iteracja tej samej pętli. Dokładnie tak działa Claude Code i Codex: jeden loop nad jedną historią, a rozgałęzienia siedzą w wywołaniach narzędzi.
Pętla kończy się strukturalnie: gdy model przestaje wołać narzędzia, czyli uznał robotę za skończoną. Nie ma tu warunku „testy zielone?", bo to agent ma doprowadzić je do zieleni, zanim powie, że skończył.
Co zostaje POZA pętlą
Tylko to, czego agentowi nie wolno zrobić samemu: przegląd zmian przez człowieka, commit budowany przez koordynatora z zaakceptowanych blobów i wypchnięcie albo scalenie. Trzy bloki, nie dlatego że tak ładniej wygląda, tylko dlatego że każdy z nich wymaga kogoś innego niż agent.
Odrzucenie w przeglądzie też nie wraca krawędzią — kończy run jako revision_requested, a koordynator startuje kolejny z uwagami. To pętla sesji, piętro wyżej niż pętla agenta.
