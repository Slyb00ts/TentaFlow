Krok 3 — Deklaracja aliasów AI

TentaVision utworzy 6 wpisów w globalnej tabeli aliasów TentaFlow (model_aliases). Każdy alias ma sugerowany domyślny target z manifestu — możesz go zostawić lub wyczyścić. Konkretne przypisanie modeli, fallbacki i strategy konfigurujesz po instalacji w Serwisy → Aliasy (globalne UI TentaFlow). Tu tylko deklarujemy że aliasy mają zostać utworzone.

Co się stanie po finalizacji

TentaFlow wykona create_or_reactivate_model_alias() dla każdego z 6 aliasów w globalnej tabeli model_aliases. Sugerowane domyślne targety zostaną zapisane jako target_model, ale nie weryfikujemy czy taki model jest faktycznie zarejestrowany. Po instalacji przejdź do Serwisy → Aliasy i:

  • Przypisz konkretne target_model (jeśli sugerowany default nie istnieje w deployment)
  • Dodaj fallback_targets (chain failoverowy)
  • Wybierz strategy (first_available · round_robin · weighted)
  • Aktywuj gated aliasy gdy claims D4 zostaną spełnione

Krok 2 — Storage (ukończone)

Manifest deklaruje: KV + SQL (dwa backendy obsługiwane: SQLite, PostgreSQL). Wybrano:

KV storeaktywny — wspólna baza TentaFlow (limit 10k kluczy)
SQL backendSQLite — per-addon plik ~/.tentaflow/addons/tentavision/data.db
DialectANSI — przenośność, można migrować na PostgreSQL później
Migrations6 plików w migrations/ · zostaną uruchomione po finalizacji
Vector namespaces4 namespaces: attributes, plates (B), faces, persons (C — locked)
Encryptionat-rest (SQLCipher włączony)
