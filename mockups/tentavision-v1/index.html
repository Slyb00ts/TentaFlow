TentaVision

Addon TentaFlow do analizy obrazu z kamer — pełny zestaw mockupów UI v1, zgodnie z planem v0.2 (po konsultacji codex).

Architektura

Natywny runtime video analytics + addon WASM jako control plane. Wąskie API VideoAnalyticsRuntime, handle-based.

RODO / AI Act

Twarde bramy DPIA/FRIA dla klasy C (D4). Art. 5 i Annex III egzekwowane na poziomie runtime, nie tylko UI.

Stylistyka

Komponenty tf-*, paleta TentaFlow (Manrope, dark indigo/violet). Wszystkie ekrany 1440 × 820.

M1

Dashboard

KPI systemu, ostatnie alarmy, heatmapa aktywności 24h × kamera.
M2

Live view (grid kamer)

Grid 1/4/9/16, overlay bbox per detektor, fullscreen z timeline.
M3

Kamery — lista & wizard

tf-table + wizard "dodaj kamerę" (discovery → creds → preview → profil).
M4

Profile analityczne

Builder grafu operatorów, przypisanie do kamer, harmonogram dzień/noc.
M5

Centrum alarmów

Feed real-time, karta alarmu z klipem 30s, workflow potwierdzania.
M6

Wyszukiwarka historyczna

Text / atrybut / podobieństwo / tablica → wyniki + eksport.
M7

Re-ID (D4) — pod legal gate

PIN + role + LegalGrant. Galeria z TTL. Audit query.
M8

Modele i runtime

Lista modeli, benchmark, rollback, ONNX upload, budżet VRAM.
M9

Strefy, harmonogramy, reguły

Polygon editor, kalendarz tygodniowy, reguły AND/OR.
M10

Audyt + RODO

Hash-chain log, retencja per klasa, generator DPIA/FRIA.
M11

Eksport dla służb

Paczki dowodowe (HSM/TSA signed), uprawnieni odbiorcy, log eksportów.
M12

Ustawienia addona

Storage, backendy inference, powiadomienia, licencje, integracje.
M13

Onboarding wizard (legal)

Rola wdrożenia → profil prawny → pierwsza kamera → presety.
M14

Bindings & Storage

Mapowanie 6 aliasów AI na konkretne services + stan wbudowanych API (KV/SQL/Vector/Recording).
M15

Install wizard

6 kroków instalacji: permissions → storage backend → deklaracja aliasów AI → Flow templates → profil prawny → pierwsza kamera.
M16 · systemowy

Serwisy → Aliasy (globalny UI TentaFlow)

Nie należy do TentaVision — to globalne UI w TentaFlow Services. Admin konfiguruje wszystkie aliasy z różnych addonów: target_model, fallback_targets, strategy.
M8b · systemowy

Model detail → Dostęp i konsumenci

Drill-down do pojedynczego modelu z M8: visibility (private/restricted/public) + tabela addonów-konsumentów z statusami grantów + statystyki użycia per consumer.
M12b · systemowy

Ustawienia addona → zakładka „Dostęp”

Rozszerzenie M12: aliasy/modele które addon używa (z uses_alias) oraz reverse view zasobów które addon udostępnia innym z linkami do M16b/M8b.
M15b · systemowy

Install wizard → Krok 4 (Zewnętrzny dostęp)

Nowy krok wizardu: karty per uses_alias/uses_model — auto-grant dla public, radio Zaakceptuj/Odrzuć dla restricted, blokada dla private.
M16b · systemowy

Aliasy → Konsumenci (rozwinięty wiersz)

M16 z rozwiniętym wierszem aliasu: panel visibility (3-stanowy segmented), tabela konsumentów (granted/pending/revoked) + audit log grantów.
