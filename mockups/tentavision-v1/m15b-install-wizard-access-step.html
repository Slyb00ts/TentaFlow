Co zatwierdzasz w tym kroku

TentaVision prosi o dostęp do następujących aliasów i modeli należących do innych addonów lub konfiguracji systemowej. Dostęp wymagany dla funkcji oznaczonych required blokuje uruchomienie addona jeśli odrzucisz. Pozycje optional są bezpieczne do odrzucenia — addon sam radzi sobie z brakiem (np. fallback do alternatywnej ścieżki).
teams-stt alias owner: teams-bot public required
Transkrypcja audio z mikrofonów kamer do logów BHP — wymagane dla raportu incydentów Art. 207 KP.
Grant automatyczny. Alias jest publiczny — każdy addon z deklaracją uses_alias dostaje dostęp natychmiast po instalacji. Nie musisz nic robić.
yolov8-pose-v3 model owner: manual:admin.krystian restricted required
Wykrywanie upadków u pacjentów geriatrycznych — primary input dla D2 (action recognition). Model wytrenowany na danych medycznych.
Model systemowy — admin ma whitelist konsumentów. TentaVision zostanie dodany do listy po Twojej akceptacji.
default-llm alias owner: manual (admin) restricted optional
Klasyfikacja kontekstu alarmu (skąd, kto, co) dla operatora — opcjonalne wzbogacenie raportu. Bez grantu kontekst tworzony jest z reguł heurystycznych.
Alias systemowy zarządzany przez administratora TentaFlow.
erp-employee-lookup alias owner: hr-bridge private optional
Identyfikacja pracownika po ID karty — alternatywa do D4 face dla deploymentów bez DPIA.
Brak dostępu. Owner hr-bridge nie udostępnia tego aliasu nikomu (visibility = private). Skontaktuj się z administratorem hr-bridge aby zmienił visibility na restricted i dodał TentaVision do whitelisty. Ten krok wizardu pominie tę deklarację — addon wystartuje (optional).
Zaakceptowane: 2/3 · auto-grant: 1 · pominięte: 1 (private)
