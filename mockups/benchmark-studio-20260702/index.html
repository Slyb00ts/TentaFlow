Benchmark Studio

Benchmarki wydajności modeli LLM przez API — jak llama-bench, ale dla całych serwisów w mesh TentaFlow i zewnętrznych API. User zakłada benchmark, wybiera targety (nasze serwisy + zewnętrzne endpointy), wybiera testy, uruchamia i ogląda wyniki: tabele mean ± σ, wykresy, porównania historycznych runów. Mockupy v1.

Targety = serwisy i API

Benchmark odpala te same testy przeciw wielu targetom naraz: serwisy z mesh (vLLM, llama.cpp — wybierane checkboxem z listy) oraz zewnętrzne API (OpenAI-compatible, Anthropic) dodawane ręcznie: host, port, klucz, model.

Metryki jak llama-bench

TTFT (ms), prefill tok/s, decode tok/s, total ms, latencje p50/p90/p99, throughput przy N równoległych, error rate, stabilność w czasie. Każdy wynik to mean ± σ z N powtórzeń — nie pojedynczy pomiar. Bez kosztów.

Historia i regresje

Każdy run zapisany w historii. Porównanie Run A vs Run B (np. przed/po update silnika) z tabelą delt Δ% i automatyczną sekcją „Regresje" — spadek decode tok/s przy ctx 32k widać od razu.

M1

Lista benchmarków

Karty benchmarków: targety, testy, ostatni run (status + data), mini-sparkline trendu decode tok/s. Sekcja „Ostatnie runy" z historią.
M2

Kreator — targety (1/2)

Nazwa benchmarku + wybór targetów: serwisy z mesh (checkbox, model, node, silnik, status) i zewnętrzne API (typ, host, port, klucz, model).
M3

Kreator — testy (2/2)

Karty testów z toggle i parametrami: latencja pojedyncza, sweep równoległości, sweep kontekstu, sustained load. Estymacja czasu i „Uruchom".
M4

Run w toku

Progress całości, macierz statusów target×test (done/running/pending), live log monospace, częściowa tabela wyników rosnąca na żywo.
M5

Wyniki runu

Tabela à la llama-bench (mean±σ, p50/p90/p99, err%), wykresy: decode per równoległość, degradacja vs kontekst, latencje, timeline stabilności.
M6

Porównanie runów

Run A vs Run B (np. gemma-4 przed/po update silnika): tabela delt Δ% zielony/czerwony, słupki A-vs-B, sekcja „Regresje" z chipami ostrzeżeń.
