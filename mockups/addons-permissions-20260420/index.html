Addons (WASM) — docelowy model uprawnień i OAuth

Trzy niezależne, nakładające się osie: kto widzi addon (visibility / grupa), co może robić (function-level permissions per grupa) i czyim kontem to się loguje (OAuth global vs individual). Każda oś zarządzana w osobnej zakładce detail panelu, plus końcowa zakładka dla administratora do podglądu tokenów użytkowników i osobny widok "Moje konta" dla zwykłego użytkownika.

Visibility (widoczność)

Admin wybiera, które grupy w ogóle widzą addon w katalogu. Grupa bez widoczności — addon nie istnieje dla niej.

Function permissions

Dla każdej grupy — macierz funkcji addona (czytaj, pisz, usuwaj...). Grupa X tylko czyta Teams; Grupa Y czyta i pisze.

OAuth mode

Global: admin raz podłącza konto, wszyscy go używają (read-only dla userów). Individual: każdy user loguje się swoim kontem OAuth.

Tryb uwierzytelniania OAuth

Określa, czyje konto Microsoft/Google/... jest używane przy wywołaniach API z poziomu tego addona.

Global (shared account)

Admin raz podłącza jedno konto serwisowe (np. bot@firma.com). Wszyscy użytkownicy z dostępem korzystają z tego samego tokena. User nie może zmienić ani odłączyć konta.

Użyj gdy: bot-y serwisowe, wspólne dashboardy, brak personalizacji per-user.

Individual (per-user account)

Każdy użytkownik loguje się własnym kontem OAuth. Addon działa w imieniu użytkownika (RODO-friendly, audit trail per osoba, personalizowany access).

Użyj gdy: czyta prywatne wiadomości, wysyła w imieniu usera, integracja z kalendarzem, skrzynkami mailowymi.
Zmiana trybu dotyka 12 aktywnych połączeń. Przełączenie z individual na global odłączy wszystkie tokeny userów. Przełączenie z global na individual usunie konto shared i zmusi każdego usera do ponownego połączenia.

Dane providera OAuth (client credentials)

Dane aplikacji zarejestrowanej w Azure/Google/... Wspólne dla wszystkich trybów.
Teams.Read Chat.ReadWrite OnlineMeetings.Read User.Read

Informacja dla trybu individual

W trybie individual powyższe dane (Client ID / Secret) są używane tylko do inicjacji flow OAuth. Każdy użytkownik przechodzi przez standardowy consent screen Microsoft/Google i sam autoryzuje aplikację. Tokeny zapisywane są w user_oauth_accounts (szyfrowane per-user), refresh odbywa się automatycznie.

Nowe tabele DB (migracja 38)

-- 1. Konfiguracja providera OAuth per addon
CREATE TABLE addon_oauth_config (
  id INTEGER PRIMARY KEY,
  addon_id TEXT NOT NULL UNIQUE,
  provider TEXT NOT NULL,                    -- 'microsoft' | 'google' | 'github' | 'custom-oidc'
  client_id TEXT NOT NULL,
  client_secret_encrypted BLOB NOT NULL,     -- AES-256-GCM
  tenant_id TEXT,
  oauth_mode TEXT NOT NULL CHECK (oauth_mode IN ('global','individual')),
  global_account_token_encrypted BLOB,       -- tylko gdy mode = 'global'
  global_account_email TEXT,
  redirect_uri TEXT NOT NULL,
  configured_by INTEGER REFERENCES user_accounts(id),
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL
);

-- 2. Widoczność addonu per grupa
CREATE TABLE addon_group_visibility (
  id INTEGER PRIMARY KEY,
  addon_id TEXT NOT NULL,
  group_id INTEGER NOT NULL REFERENCES user_groups(id) ON DELETE CASCADE,
  visible INTEGER NOT NULL DEFAULT 1,
  UNIQUE (addon_id, group_id)
);

-- 3. Per-user, per-addon zapisane tokeny OAuth (mode='individual')
CREATE TABLE user_oauth_accounts (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES user_accounts(id) ON DELETE CASCADE,
  addon_id TEXT NOT NULL,
  provider TEXT NOT NULL,
  account_email TEXT NOT NULL,
  account_display_name TEXT,
  access_token_encrypted BLOB NOT NULL,
  refresh_token_encrypted BLOB,
  expires_at DATETIME,
  scopes TEXT NOT NULL,                      -- JSON array
  created_at DATETIME NOT NULL,
  last_used_at DATETIME,
  UNIQUE (user_id, addon_id)
);

-- 4. Per-grupa granty uprawnień (rozszerzenie istniejącego addon_permissions)
--    użyj subject_type='group' na istniejącej tabeli + dodaj resource_name TEXT
ALTER TABLE addon_permissions ADD COLUMN resource_name TEXT;  -- np. "teams.read_messages"
CREATE INDEX idx_addon_perms_lookup ON addon_permissions(addon_id, subject_type, subject_id, permission_id, resource_name);

Rozszerzenie addon.toml (manifest)

[addon]
id = "teams-bot"
name = "Microsoft Teams Bot"
version = "0.5.2"

# NOWE: Deklaracja OAuth providera
[[oauth_provider]]
provider = "microsoft"
scopes = ["Teams.Read", "Chat.ReadWrite", "OnlineMeetings.Read", "User.Read"]
supported_modes = ["global", "individual"]    # które tryby są dozwolone
default_mode = "individual"

# NOWE: Deklaracja funkcji (permissions) per-resource
[[permission]]
id = "teams.read_messages"
display_name = "Read Teams messages"
description = "Odczyt wiadomości z kanałów i czatów"
risk = "low"                                   # low | medium | high

[[permission]]
id = "teams.send_message"
display_name = "Send Teams messages"
description = "Wysyłanie wiadomości w imieniu użytkownika"
risk = "medium"

[[permission]]
id = "teams.capture_audio"
risk = "high"
# ...

# NOWE: Domyślna widoczność
[visibility]
default = "admin_only"   # admin_only | all_groups | listed
# jeśli default = "listed":
# groups = ["Sales Team", "Customer Support"]

AddonGroupPermissionsListRequest   { addon_id }                    → matrix [group × permission]
AddonGroupPermissionUpdateRequest  { addon_id, group_id, perm_id, grant: allow|deny|inherit }

AddonOAuthConfigGetRequest         { addon_id }
AddonOAuthConfigUpdateRequest      { addon_id, provider, client_id, client_secret, tenant_id, mode, redirect_uri }
AddonOAuthTestConnectionRequest    { addon_id }                    → {ok, error?}
AddonOAuthModeSwitchRequest        { addon_id, new_mode }          → {affected_users_count}

AddonLinkedAccountsListRequest     { addon_id }                    → [UserOAuthAccount]  (admin-only)
AddonLinkedAccountRevokeRequest    { addon_id, user_id }

UserOAuthAccountsListRequest       { }                             → [własne accounty userów]
UserOAuthInitiateRequest           { addon_id }                    → {authorize_url}
UserOAuthCallbackRequest           { addon_id, code, state }       → {account_email}
UserOAuthDisconnectRequest         { addon_id }
