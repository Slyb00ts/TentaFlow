TentaFlow CRM v1

Pełny zestaw mockupów UI dla CRMa TentaFlow oraz powiązanych addonów (Contacts, Activity, Documents, Billing, Calendar). Każdy addon jest aplikacją w sekcji „Moje aplikacje” lewego menu TentaFlow. Renderuje się w prawej części z własnymi pill-tabs u góry — nie zastępuje globalnego menu. Wzajemna komunikacja idzie przez deklaratywne kontrakty Resource Provider + View Contributions, a AI ma osobny Tool Broker z autoryzacją per-grant i confirm dialogiem dla mutacji.

Filozofia

Daily Sales Inbox jako główny ekran handlowca, nie kanban. AI jako cichy administrator (suggest / draft / act), nie chatbot. Ten sam silnik widgetów dla zarządu, dyrektora i handlowca — różne query, nie 3 osobne produkty.

Addon-as-App

Globalne lewe menu TentaFlow zostaje wspólne dla wszystkich addonów. Addon renderuje się w prawej części z własnymi pill-tabs u góry. Inny addon = inny item w sekcji „Moje aplikacje” TentaFlow. Sekcje z innych addonów wpinają się przez contrib-tag (np. „Faktury” w Contacts pokazane przez Billing).

Stylistyka

Manrope, paleta indigo/violet, komponenty tf-*, ekrany 1440×820. Bez emoji, bez własnych prymitywów. CRM ma być szybki, żywy, przewidujący.

CRM — rdzeń sprzedażowy
C1

Daily Sales Inbox (handlowiec)

Główny ekran: „dziś 7 rzeczy do zrobienia”. Kolejka decyzji + jedno kliknięcie do next-action.
C2

Pipeline kanban

Drugorzędny widok dealów. Kolumny po fazach, kolory commit/stale, wartości po PLN.
C3

Deal detail

Unified timeline (maile + spotkania + notatki + koszty), inline edit, sidebar z contributions z innych addonów.
C4

Deal create (AI-assisted)

Natural language → confirm z diffem → zapis. Pełnoekranowy formularz jako alternatywa.
C5

Dashboard handlowca

Mój cel, mój pipeline, moje ryzyko. Widgety + sekcja „Wymaga uwagi” auto-generowana.
C6

Dashboard dyrektora

Sekcja, ranking handlowców, gdzie się sypie, fikcyjne commity, oferty bez follow-upu.
C7

Dashboard zarządu

Pipeline ważony PLN, forecast, marża, ranking sekcji, ryzyka pieniężne. Ten sam silnik widgetów.
C8

Forecast workbench

Commit vs best case, snapshoty w czasie, odchylenie od celu.
C9

Karta akceptacji budżetu

Mail z 3 linkami (accept/decline/view) → status w deal. Migracja z IntrAppa, czystsze UI.
C10

Refakturowanie kosztów

E-dokument kosztowy → rozksięgowanie na deale → workflow akceptacji.
C11

AI chat sidebar + confirm dialog

Chat kontekstowy. „Załóż deal dla mBank 50k Q3” → diff → klik → zapis. Audit log per call.
C12

Smart inbox / „Wymaga uwagi”

Adaptacyjna kolejka zdarzeń wymagających decyzji. Reguły + sygnały + AI.
C13

Command palette ⌘K

Globalna nawigacja + akcje + wyszukiwanie + AI tools. Linear-style, ale tematyczny.
C14

Stages settings

Edytor pipeline'u. Fazy, prawdopodobieństwa, wymagane pola, automatyzacje.
Contacts — centralna baza encji
K1

Contacts — lista

Firmy + osoby + grupy kapitałowe w jednym widoku. Smart lists, segmenty, masowe akcje.
K2

Osoba — detail z contributions

Sekcje wpięte przez inne addony: Deale (CRM), Spotkania (Calendar), Maile (Email), Faktury (Billing). Pokazuje pattern.
K3

Firma — detail

Hierarchia (grupa kapitałowa), osoby kontaktowe, pipeline na firmie, finanse, ryzyko.
K4

Mapa relacji

Graf powiązań osób w firmie + decydenci + influencerzy. Single-context widok.
Activity / Documents / Billing / Calendar — wspierające
A1

Activity timeline

Wspólna warstwa zdarzeń: tasks, reminders, calendar events, timeline events. Karmi Daily Inbox.
D1

Documents

Pliki + metadane. Bez logiki finansowej (to billing). Renderer PDF kart akceptacji.
B1

Billing — faktury sprzedaży

Wystawione + zapłacone + przeterminowane. Numer faktury jako styk z KSeF.
B2

Billing — kosztorys (e-dokumenty)

Inbox dokumentów kosztowych do rozksięgowania. Workflow akceptacji na deal.
L1

Calendar — tydzień

Sync spotkań + kontekst dealowy w evencie. Meeting assistant w widoku spotkania.
Platform — kontrakty addonów + AI
P1

App switcher (addon-as-app)

Globalne przejście między CRM / Contacts / Activity / Billing / itd. Z preview ostatniej aktywności.
P2

Permissions matrix

Per-instance grants między addonami. Kto kogo czyta/pisze. Audit kto kiedy zatwierdzał.
P3

AI Tools registry

Globalna pula narzędzi AI z konkretnych addonów. Risk per tool, confirmation, audit.
O1

Struktura organizacyjna

Edytor drzewa stanowisk firmy. Hierarchia = automatyczna widoczność danych w addonach. Wakaty, podwładni, transitive view.
O2

Katalog ról

CRUD na rolach (Handlowiec/PM/Architekt/Sponsor…). Każda ma kind + flagi (is_manager / can_edit_deal / can_approve) + scope widoczności.
