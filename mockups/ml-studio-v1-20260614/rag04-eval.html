ML Studio — Ewaluacja + Playground + Deploy (RAG)

Indeks z poprzedniego kroku odpytujemy zestawem pytań testowych i liczymy metryki retrieval na realnych trafieniach — każda metryka jest średnią po 48 pytaniach. Playground pokazuje odpowiedź z cytowaniem fragmentów (dokument + strona), więc nic nie jest „wymyślone”. Na końcu wdrażasz endpoint RAG z manifestem opisującym dokładnie embedding, indeks i reranker.

48 pytań = źródło metryk

recall@5, MRR i nDCG@10 to średnie policzone na 48 pytaniach z odpowiedziami referencyjnymi.

Odpowiedź z cytowaniem

Każda odpowiedź wskazuje fragmenty źródłowe (dokument + strona) jak przypisy — zero halucynacji bez źródła.

Manifest = pełna receptura

Deploy zapisuje embedding=bge-m3, index=hnsw, reranker, top_k — endpoint odtwarza dokładnie ten pipeline.

Deploy — endpoint RAG
Manifest opisuje dokładnie pipeline z poprzednich kroków
domyślne
Lokalnie (w tym węźle)
Endpoint dostępny przez protokół binarny TentaFlow. Indeks i modele zostają na tym węźle.
Zewnętrznie (REST /v1)
Endpoint OpenAI-kompatybilny dla aplikacji zewnętrznych. Auth: API key (Bearer).
# manifest endpointu RAG — odtwarza pipeline z kroków Korpus → Chunking → Indeks type = "rag-endpoint" name = "baza-wiedzy-adr" [corpus] documents = 12 # z kroku Korpus pages = 640 [chunking] strategy = "by_headings" chunk_size = 512 overlap = 64 chunks = 2480 # policzone z 640 stron × strategii [embedding] model = "bge-m3" # z Biblioteki zasobów (capability=embedding) dim = 1024 [index] backend = "hnsw" # vector_* m = 16 ef_construction = 200 [reranker] enabled = true model = "bge-reranker-v2-m3" [retrieval] top_k = 5 fetch_before_rerank = 20
Manifest nie zawiera ani jednej wartości spoza wcześniejszych kroków: 12 dokumentów / 640 stron (Korpus), 2 480 fragmentów i bge-m3 (Chunking), hnsw M=16/ef=200 (Indeks), top_k=5 + reranker (ten ekran). Endpoint odtwarza dokładnie ten sam pipeline przy każdym zapytaniu.
