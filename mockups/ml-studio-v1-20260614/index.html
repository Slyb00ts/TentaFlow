TentaFlow ML Studio

Projekt-centryczny moduł ML: zaczynasz od Projektów, tworzysz nowy kreatorem (typ determinuje resztę), a wewnątrz projektu konfigurujesz schemat, oznaczasz dane i trenujesz. Wizardy pokazują KAŻDY krok z realnymi polami i pomocą kontekstową — widać JAK zbudować rzeczy od zera, nie tylko stan końcowy.

v2 — projekt-centryczny. Start = Projekty. Każdy z 6 typów projektu ma pełną ścieżkę od kreatora do wdrożonego modelu. Globalne (cross-project) są tylko dwa: Rejestr modeli i Biblioteka zasobów.
v2.1: projekty per-właściciel + zaproszenia; ML Studio w Aplikacjach (widoczne tylko dla Power Userów); zasoby przydzielane mesh-wide (admin daje GPU z dowolnego noda osobie / grupie / projektowi); baza synchronizowana między nodami, a trening może być rozproszony na wiele nodów.
1 · Start i nawigacja globalna
P0 · START

Projekty

Ekran główny modułu: projekty jako karty (Rozpoznawanie na cysternach, Trening Guard, RAG), status, aktywność, „+ Nowy projekt”.
P1

Kreator projektu

Router typu: nazwa → typ (rozpoznawanie / fine-tune LLM / RAG / anomalie / destylacja / vision-audio) → dane → schemat. Typ determinuje kroki.
Zglobalny

Biblioteka zasobów

Cross-project: modele usług (capability matrix), słowniki lookup, źródła danych, dostępy zewnętrzne. ŹRÓDŁO list w kreatorach całego modułu.
M7globalny

Rejestr modeli

Wszystkie wytrenowane modele wszystkich projektów: metryki, wersje, krzywe, Deploy / Użyj. Każdy model linkuje do projektu-źródła.
1b · Uprawnienia i zasoby (v2)
Projekty są per-właściciel z zaproszeniami; zasoby (GPU/CPU/RAM) przydziela administrator z puli wszystkich nodów mesh. Bez przydziału trening się nie uruchomi.
P2

Udostępnianie projektu

Członkowie projektu + zaproszenie po użytkowniku / e-mailu, role owner / editor / viewer. Właściciel zaprasza i odbiera dostęp.
AZadmin

Zasoby (alokacja mesh)

Pula GPU/CPU/RAM wszystkich nodów mesh; przydział do osoby / grupy / projektu z limitem; aktywne przydziały. Domyślnie pula pusta.
2 · Projekt: Rozpoznawanie obrazu
P·O

Przegląd projektu

Zakładka wnętrza projektu: KPI (zdjęcia, klasy, % oznaczone, modele), ostatnie joby, modele projektu, szybkie skróty. Zastępuje rolę m01.
A·D

Dane

Import zdjęć, profil zbioru, zbiór anotacji (144) vs wszystkie (248), podgląd i statystyki klas.
R1

Schemat zadania

Edytor klas i atrybutów od zera: kolor/kształt, typ atrybutu (lista / tekst / OCR / liczba / klasyfikator), OCR + lookup UN.
R2

Anotacja

3 kolumny: zdjęcia, obraz z edytowalnymi ramkami, klasy + panel atrybutów (OCR „odczytaj”) + „⚡ Pre-oznacz modelem”.
A·T

Trening

Konfiguracja i uruchomienie treningu detektora (RF-DETR) na zbiorze anotacji projektu, postęp jobu.
A·E

Ewaluacja

mAP per klasa, macierz pomyłek, przykłady FP/FN, porównanie wersji modelu.
A·X

Eksport

Matryca format×kwant bramkowana możliwościami (ONNX / TensorRT / CoreML / HF), deploy do serwisu.
3 · Projekt: Fine-tuning LLM (Guard)
F0

Model bazowy

Krok 1: wybór modelu bazowego (Qwen3.5-0.8B / Llama-Guard / własny HF repo), pobranie wymaga hf_token.
F·D

Dane

Krok 2: upload lub generacja danych + augmentacja zero-width, split train/eval, format (text, label).
F1

Metoda treningu

Krok 3: dwie prostopadłe osie — algorytm/cel (SFT/DPO) × parametryzacja (QLoRA/LoRA/DoRA/Full) z auto-estymatą VRAM i hiperparametrami.
F2

Trening na żywo

Live wykres loss+eval, pasek epoki/kroków, metryki, gauge VRAM, logi mono, Anuluj / Wznów, checkpointy.
F3

Eksport + deploy

Formaty (GGUF / NVFP4 / MLX / ONNX / HF), benchmark wariantów vs baseline Claude (per-class P/R/F1, tok/s), deploy + TOML.
4 · Projekt: ML tabelaryczne + anomalie
Zastępuje stary m04 — pełne pochodzenie kolumn i klas (źródło danych → role pól → cel → silnik).
T·D

Dane (profil)

Źródło tabelaryczne (xlsx/parquet/DB), profil kolumn z typami i mapowanie pól → role. Pochodzenie każdej kolumny.
T1

Cel zadania

Wybór celu: klasyfikacja / regresja / wykrywanie anomalii; kolumna celu i metryka z profilu danych.
T2

Silnik

Karty silników (AutoGluon / PyOD / …) dobrane do celu, z parametrami i budżetem czasu.
T3

Leaderboard

Ranking modeli AutoML z metrykami i paskami, najlepszy wyróżniony, wykres.
T4

Ewaluacja

Metryki finalnego modelu, ważność cech, krzywe; dla anomalii: progi i przykłady wykryć.
5 · Projekt: RAG
RAG1

Korpus

Podpięcie dokumentów (PDF/MD), profil korpusu, czyszczenie i ekstrakcja tekstu.
RAG2

Chunking

Strategia dzielenia (rozmiar/overlap), podgląd chunków, embedder z biblioteki zasobów.
RAG3

Indeks

Budowa indeksu wektorowego (HNSW), parametry, postęp embeddowania.
RAG4

Ewaluacja

Zapytania testowe, trafność (recall@k), reranking, odpowiedzi z cytowaniem źródła.
6 · Projekt: Destylacja
D1

Para nauczyciel→uczeń

Wybór modelu nauczyciela (Qwen3.6-27B) i ucznia, cel destylacji.
D2

Prompty / zbiór

Zbiór promptów do generacji odpowiedzi nauczyciela, podgląd i augmentacja.
D3

Trening ucznia

Trening na odpowiedziach nauczyciela (live loss, VRAM, checkpointy).
D4

Porównanie

Uczeń vs nauczyciel: jakość, tok/s, rozmiar, koszt — zysk z destylacji.
7 · Projekt: Fine-tuning vision / audio / obraz
C1

Model bazowy

Wybór modelu vision/audio/obraz-gen (Whisper / detektor / diffusers), pobranie z HF.
C·D

Dane

Zbiór (nagrania + transkrypty / obrazy + opisy), profil i split.
C·M

Metoda

Metoda fine-tuningu właściwa dla modalności (LoRA / pełny / adaptery) z estymatą VRAM.
C·T

Trening

Live trening modelu vision/audio: loss, metryki modalności, logi.
C·X

Eksport

Matryca formatów (CoreML / ONNX / MLX / HF) bramkowana modalnością i HW, deploy.
