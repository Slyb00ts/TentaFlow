ML Studio — Eksport i deploy modelu vision (RF-DETR)

Ostatni etap: eksport wytrenowanego detektora do formatu produkcyjnego. Matryca nie jest globalna — dostępność formatu zależy od typu modelu i hardware (capability-gated). Dla modelu VISION dostępne są ONNX, TensorRT, CoreML, HuggingFace; formaty LLM-only (GGUF, MLX-LLM) są wyszarzone z wyjaśnieniem. Kwantyzacje pokazywane są właściwe dla wybranego formatu, a rozmiary przed konwersją to „szacowany ~".

Bramkowanie możliwościami

GGUF/MLX-LLM wyszarzone — dotyczą LLM, nie modelu detekcji. Tooltip mówi „dlaczego".

Kwantyzacje per format

ONNX ma FP32/FP16/INT8, TensorRT FP16/INT8, CoreML palettize — nie jedna globalna siatka.

Multi-select paczki

Zaznacz kilka wariantów (np. ONNX FP16 + TensorRT INT8) i wyeksportuj jedną paczką.

Krok 2 — Deploy

Lokalnie do models/ + TOML
Skopiuj ONNX do models/rozpoznawanie-adr/, wygeneruj manifest deploy (onnxruntime), zarejestruj w serwisie. Dostępny przez service_request.
Zewnętrzny endpoint
Wypchnij na zewnętrzny serwer inferencji (Triton / własny). Wymaga skonfigurowanego dostępu (Settings → Dostępy zewnętrzne).
# wygenerowany manifest deploy (models/rozpoznawanie-adr/deploy.toml) name = "rozpoznawanie-adr" engine = "onnxruntime" model_file = "rozpoznawanie-adr-fp16.onnx" task = "object-detection" input_resolution = 560 classes = ["tablica_adr", "tablica_rejestracyjna", "nalepka", "znak_srodowiskowy", "termometr"]

classes i input_resolution nie są wpisane ręcznie — pochodzą ze Schematu (5 klas) i kroku Trening (560 px).
