Destylacja — porównanie nauczyciel vs uczeń, eksport

Ostatni krok: zestawienie nauczyciela, ucznia po destylacji i ucznia bazowego (bez KD) na zestawie ewaluacyjnym. Cel destylacji = uczeń odzyskał większość jakości nauczyciela przy ~34× mniejszym rozmiarze i ~8× szybciej. Potem eksport ucznia do formatu produkcyjnego i deploy do models/ z manifestem TOML.

Retencja jakości

Uczeń 0.88 / nauczyciel 0.94 = 94% jakości zachowane mimo 34× mniejszego modelu.

Przyspieszenie

95 tok/s vs 12 tok/s ≈ 8× szybciej, lokalnie, bez kosztu API.

Eksport + deploy

GGUF / ONNX / MLX / HF → models/ + manifest TOML (distilled_from).

Eksport ucznia — format

Uczeń to LLM, więc dostępne formaty są bramkowane zdolnością (LLM). Dla GGUF wybierz poziom kwantyzacji.

GGUF (llama.cpp) ONNX (onnxruntime) MLX (macOS) HuggingFace (safetensors)

Deploy ucznia

Lokalnie do models/ + TOML
Skopiuj GGUF do models/adr-assistant/, wygeneruj manifest deploy (llama.cpp), zarejestruj w serwisie. Dostępny przez service_request / llm_generate.
Zewnętrzny endpoint
Wypchnij do vLLM / HF Inference Endpoint. Wymaga skonfigurowanego dostępu (Settings → Dostępy zewnętrzne).
# wygenerowany manifest deploy (models/adr-assistant/deploy.toml) name = "adr-assistant" engine = "llama.cpp" model_file = "adr-assistant-Q4_K_M.gguf" quantization = "Q4_K_M" context_size = 2048 task = "adr-assistant" distilled_from = "Qwen3.6-27B"
