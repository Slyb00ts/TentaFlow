tf-screen — jednolity shell dla wszystkich ekranów

Jeden component <tf-screen> zastępuje obecne rozbieżne wrappery (.page, .mesh-shell, .clusters-shell, .addons-screen, .mesh-detail-topbar, .cluster-detail-topbar, .detail-head). Karta wypełnia cały viewport .main, ma ramkę, zaokrąglone rogi, scrolluje tylko body (header/toolbar/tabs są sticky). Obsługuje: listę, detail (z back-btn), nested detail (breadcrumb), split-view (aside + main), taby, toolbar, actions. Wszystkie ekrany (Users, Mesh, Services, Clusters, Addons, Flows, Audit, Settings, API Keys) powinny używać tego samego szablonu.

1. List screen — header + toolbar + table
Standardowy widok listy (Users, Mesh nodes, Services, API Keys, Audit…). tf-screen z headerem, toolbarem (search + filtry) i table w body. Nie ma back-btn (to ekran top-level). Actions po prawej stronie headera.

DOM / API

  • <tf-screen> — root, flex column, wypełnia .main
  • attr: title="Użytkownicy" — renderuje .title-block
  • attr: subtitle="..." — linia subtitle
  • attr: icon="users" — ikona przy tytule (ze sprite)
  • attr: count="8" — count-badge przy tytule
  • slot="actions" — przyciski po prawej
  • slot="toolbar" — search + filtry
  • slot default — content w body (table / grid)
2. Detail screen — back-btn + tabs + split body (aside + main)
Widok detail (User detail, Cluster detail, Mesh node detail). back-btn po lewej headera → wraca do listy. Taby w osobnym pasie. Body w wariancie split: aside (stat-lines, avatar, akcje) + main (form).

DOM / API

  • attr: back — renderuje back-btn; event back emitowany przy kliknięciu
  • slot="tabs" — <tf-tabs> w pasie pod headerem
  • attr: layout="split" — body jako grid aside + main
  • slot="aside" — zawartość lewej kolumny (avatar, stat-lines, akcje)
  • slot default — main content (form, perm-matrix itp.)
