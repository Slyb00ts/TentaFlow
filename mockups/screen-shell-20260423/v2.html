Body SAM scrolluje. Header (z breadcrumbem) + tabs są sticky bo są flex-shrink:0, a body ma overflow-y:auto. Żadna „karta w karcie" — tf-screen to po prostu layout wypełniający .main całej prawej strony.

Nested — zasady

  • crumbs: N poziomów — wszystkie poza ostatnim klikalne; ostatni .current
  • brak toolbaru — na detail zwykle toolbar nie jest potrzebny; tabs wystarczają
  • padded body — dla contentu innego niż table (dashboardy, forms, logi)

Zmiany vs v1

  • Shell nie jest kartą — wypełnia całą prawą stronę .main (flex column overflow:hidden), bez border-radius, bez ramki
  • Breadcrumb w headerze (nad h1, małe uppercase litery) — zastępuje back-btn jako główny mechanizm nawigacji wgłąb
  • Brak back-btn — breadcrumb daje więcej kontekstu i pozwala skakać o N poziomów, nie tylko o 1
  • Header jako jeden pas bg-2 — z ico-tile 36px, h1 17px, sub 12px. Zgodnie z meeting-bot
  • Body scrolluje się samo — header/tabs/toolbar to flex-shrink:0, body to flex:1 overflow-y:auto. Scrollbar jest TYLKO w body, nie w całym .main
  • Split ma overflow:hidden + aside i main-col mają własne overflow-y:auto — dwa niezależne scrolle dla stron z długim aside (np. lista członków grupy)
